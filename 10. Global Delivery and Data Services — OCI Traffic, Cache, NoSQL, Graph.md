## Global traffic and acceleration

- Use regional public Load Balancers for HTTP/HTTPS ingress and Network Load Balancers for appropriate L3/L4 workloads.
- Use **Traffic Management steering policies** and **Health Checks** for DNS-level global routing, failover, weighted rollout, geolocation, or AS-path decisions.
- DNS steering is subject to TTL/resolver caching. It does not accelerate arbitrary TCP/UDP in the same way a global anycast accelerator design might.
- Combine global routing with regional application capacity, replicated data, tested failover, and documented RTO/RPO.

## Cache, NoSQL, graph, and ledger reasoning

- A cache improves read latency/load but needs explicit invalidation/expiry/failure behavior. Never assume it provides durable source-of-truth semantics.
- Oracle NoSQL is selected after validating data model, index/query patterns, consistency, and migration. An AWS Keyspaces/DynamoDB client assumption is a false equivalence.
- Select a graph database/pattern only when relationship traversal/query needs outweigh the operational/modeling complexity of relational or document approaches.
- For tamper-evident audit/ledger requirements, define evidence, access separation, retention, cryptographic verification, and external audit export. “Immutable” is a requirement, not a product label.
