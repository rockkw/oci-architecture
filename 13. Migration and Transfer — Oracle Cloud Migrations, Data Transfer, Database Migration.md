## Oracle Cloud Migrations (discovery, planning, execution)

- **Purpose**: automates the VM/instance migration lifecycle into OCI Compute — discover, inventory, plan, replicate, launch — as one self-service platform.
- **Discovery methods**:
  - **Agent-based (VMware)**: deploy a remote agent appliance (prebuilt VM) into the VMware environment; plugins handle discovery, disk replication to Object Storage, and health monitoring.
  - **Agentless (AWS EC2)**: connects directly from OCI to AWS via API — no agent deployed in the source account; credentials stored in OCI Vault.
  - **CSV import**: manual/other-source inventory intake when neither automated method fits.
- **Workflow phases**:
  1. **Manage Assets** — discover and inventory sources into an Inventory store; collect performance metrics into OCI Monitoring.
  2. **Plan & Migrate** — create migration projects/plans; a recommendation engine maps source specs to OCI shapes and generates cost estimates from the OCI rate card; supports incremental replication.
  3. **Verify** — integrates with Resource Manager (Terraform-based) to launch and validate target resources.
- Related service worth knowing exists: **Oracle Cloud Bridge**, referenced alongside Cloud Migrations for discovery/inventory — verify its exact scope/overlap if it comes up on the exam, since it wasn't independently confirmed here.

## Data transfer options (offline and edge)

- **OCI Data Transfer Disk**: ship your own HDDs to Oracle (up to 10 disks per transfer package). Encryption keys are stored in OCI, separate from the physical drives, so data stays protected if a drive is lost or intercepted in transit.
- **OCI Data Transfer Appliance**: Oracle-supplied appliance for larger migrations, up to 150 TB per appliance — order multiple appliances for petabyte-scale transfers. Process: receive appliance → up to 30 days to copy data locally → ship back to the nearest Oracle data transfer site → Oracle uploads to your Object/Archive Storage over high-speed internal connections. No cost to use; Oracle covers shipping.
- **Oracle Roving Edge Infrastructure (RED)**: rugged, portable compute/storage nodes for disconnected or intermittent-connectivity environments; devices can cluster together. Supports local data pre-processing (filtering, compression) before syncing to OCI Object Storage via FastConnect or intermittent connections.
- **Roving Edge Ultra**: the smaller, single-device, backpack-portable variant — no external power required. This is the exam's closest match to "Snowcone-style" portability, but remember RED as a category runs real OCI services at the edge, not just transfer.
- **Exam framing**: "ship physical media" → Data Transfer Disk/Appliance, sized by data volume and whether you own the drives. "Compute/storage needed at a disconnected site, with eventual sync back" → Roving Edge Infrastructure.

## Online/automated data transfer (the DataSync gap)

- There is no single OCI-managed service that automates online file sync the way AWS DataSync does. Design this from documented patterns instead:
  - **Rclone** — Oracle's documented tool of choice for moving filesystem data (local, NAS, other clouds) into Object Storage.
  - **rsync / fpsync** — for OCI File Storage: fpsync (parallel rsync wrapper) for the initial bulk copy, then rsync for incremental sync from on-premises NFS-type sources.
  - **Resilio Connect** — a third-party partner tool Oracle documents for high-speed, wire-speed data migration to/between OCI storage services.
  - **FastConnect / Site-to-Site VPN** — the connectivity layer these tools run over. Neither is a transfer service on its own; don't conflate "the pipe" with "the sync tool."
- **Exam framing**: if a scenario describes "automated, scheduled, ongoing sync from on-prem file shares to cloud storage," there is no single named OCI service to pick — the answer is the tool (Rclone/rsync/Resilio) plus the connectivity (FastConnect/VPN) plus the target (Object Storage/File Storage), reasoned as a design, not recalled as a product name.

## OCI Database Migration Service

- **Homogeneous migrations** (primary supported path): Oracle-to-Oracle and MySQL-to-MySQL(HeatWave).
  - Oracle sources: 11g, 12c, 18c, 19c (SE/EE) — on-premises, OCI, OCI Classic, or Amazon RDS for Oracle.
  - Targets: Oracle Autonomous Database, Oracle Base Database Service, Oracle Exadata Database Service, and newer multicloud targets (Oracle Database@Azure, Oracle Database@Google Cloud).
  - **Online mode**: near-zero-downtime, uses Oracle GoldenGate replication under the hood.
  - **Offline mode**: logical (dump/load-style) migration.
- **Heterogeneous migrations** (non-Oracle source or target): handled via **Oracle GoldenGate** as a distinct product, not folded into the Database Migration Service the way AWS bundles heterogeneous support directly into DMS. Don't assume OCI Database Migration Service alone covers a SQL Server → Oracle path — that's a GoldenGate design.
- **Assessment feature** (recent addition): recommends the best migration method and checks readiness of the database/migration user before a migration runs — know this exists as a pre-migration validation step, not just a post-hoc troubleshooting tool.

## Schema conversion

- Oracle's schema-conversion capability is delivered through **Oracle SQL Developer** (a free desktop IDE with a migration repository, schema capture/conversion, and reporting for sources like SQL Server, MySQL, Sybase converting into Oracle-compatible schema/PL-SQL) — **not** a managed OCI console service.
- Treat this as a genuine gap versus AWS SCT's positioning: don't expect an "OCI SCT" service to appear as an exam answer choice for a schema-conversion requirement — the answer is SQL Developer's migration tooling, or GoldenGate for the ongoing replication side.
