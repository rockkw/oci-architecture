### Translation from AWS CloudFront notes

| AWS memory anchor | OCI service/pattern | OCI distinction |
| --- | --- | --- |
| CloudFront distribution | OCI CDN/edge delivery pattern with an approved CDN provider | OCI does not present CloudFront as a one-for-one native distribution control plane; validate the selected OCI CDN offering and origin integration. |
| CloudFront origin | Public Load Balancer, Object Storage, API origin, or approved custom origin | Origin access must be protected independently; a CDN URL alone is not origin isolation. |
| CloudFront cache behavior | CDN cache rules, origin headers, cache keys, TTLs | Define caching by content behavior and invalidation requirements, not AWS behavior names. |
| Signed URLs/cookies and OAC | Application authorization, signed URL/token pattern, IAM/Object Storage policy, WAF | There is no direct OAC equivalent. Model who can read the origin and how requests are authenticated. |
| CloudFront + WAF | OCI WAF at edge/origin | OCI WAF policies provide L7 controls; ensure the origin cannot be reached around them. |

## Edge architecture

- Place a CDN in front of public static or cacheable dynamic content when global latency, origin offload, and edge caching are requirements.
- Use a public Load Balancer/API origin for dynamic services and Object Storage for appropriate static content. Keep private application and database tiers behind the origin.
- Set cache-control behavior intentionally: immutable versioned assets can use long TTLs; personalized, authenticated, or rapidly changing responses need restricted caching.
- Design invalidation/purge, stale-content behavior, compression, TLS certificates, custom domains, logging, and health/failover before launch.
- WAF protects HTTP/HTTPS request processing; use it for OWASP-style protections, rate limiting, bot/challenge controls, and access rules.

## Origin security checklist

- Restrict direct origin access to the CDN/WAF path where the selected product supports it; otherwise enforce controls at the Load Balancer, NSG, application, and authentication layers.
- Do not expose bucket write permissions to anonymous edge clients. Use least-privilege IAM and application-mediated uploads where appropriate.
- Use OCI Certificates for TLS lifecycle and Load Balancer/WAF configuration. Certificate and DNS placement follow the OCI/partner service architecture, not ACM us-east-1 rules.
- Send edge/origin access logs to Logging or a SIEM and monitor cache hit, origin latency, error rate, and WAF blocks.

## Global routing

- OCI DNS and Traffic Management can steer users to healthy regional endpoints. DNS failover is bounded by TTL/cache behavior.
- Health Checks decide endpoint health; they do not replicate data, repair an origin, or make application sessions portable.
- For active-passive or active-active designs, combine traffic steering with regional origins, data replication, and explicit RTO/RPO.
