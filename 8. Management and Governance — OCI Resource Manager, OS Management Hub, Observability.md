## Infrastructure as code

- **Resource Manager** runs Terraform stacks. Store configuration in approved source control, use plans for review, control state access, and run drift detection.
- Separate environments with compartments, Terraform variables/state boundaries, IAM policies, and promotion workflows.
- Terraform code can change infrastructure broadly; use least-privilege execution principals, approvals, and a tested rollback/recovery plan.
- Do not hand-convert CloudFormation templates into assumed OCI equivalence; redesign resource and IAM/network semantics.
- **Drift Detection, named precisely** (a MyLearn skill check question tested
  this exact term): a Resource Manager stack feature that compares the
  **real-world current state of provisioned infrastructure** against the
  **stack's last-executed Terraform configuration**, surfacing any manual/
  out-of-band changes made outside Terraform (e.g., someone edits a security
  rule directly in the Console). Distinct from Resource Manager's other
  state-related actions — **Apply** (runs the config forward) and **Import
  State** (brings existing, non-Terraform-managed resources under Terraform
  management) — drift detection specifically diagnoses divergence, it
  doesn't fix it on its own.

**Two real distinctions a MyLearn skill check tested, both true fundamentals:**
- **Terraform is IaC, not IaaS.** Terraform is tooling that calls a
  provider's APIs to create/manage infrastructure — it hosts no
  infrastructure of its own. IaaS (e.g. OCI Compute) means the provider
  hosts infrastructure you consume; stopping Terraform never removes
  anything it created, since Terraform was never the thing running it.
- **Resource type vs. resource name — only the type is provider-specific.**
  Terraform's `resource "<TYPE>" "<NAME>" {}` syntax has two separate naming
  layers: the **type** (e.g. `oci_core_vcn`, `oci_containerengine_cluster`)
  is genuinely provider-namespaced — every resource in `terraform/` uses the
  `oci_` prefix. The **name** (e.g. `"lab_vcn"`) is an arbitrary local
  identifier you invent to reference the resource elsewhere in config, and
  has nothing to do with the provider at all.

## Operating system and access management

- **OS Management Hub** centrally manages updates for supported Oracle Linux and Microsoft Windows Server environments, including supported OCI, third-party-cloud, and on-premises systems.
- Registration/profile/group/lifecycle-environment design controls what software sources and updates apply to managed instances.
- Use **Bastion** for controlled temporary SSH access to private subnets. Combine it with IAM, NSGs, host controls, and audit logging.
- Automate routine operation safely with Events, Functions, DevOps, or suitable runbook tooling; isolate and audit principals that can change production.

## Governance and observability

- **Cloud Guard** detects risky configuration/activity and can invoke responders.
- **Security Zones** prevent policy-violating resource operations in protected compartments.
- **Cloud Advisor**, Cost Analysis, budgets, quotas, and tags support cost/governance decisions; none replaces IAM authorization.
- **Monitoring**, **Logging**, **Logging Analytics**, **Audit**, and **Service Connector Hub** support metrics, logs, analysis, evidence, and routing to other services/SIEMs.
- Use compartments and tag namespaces to define ownership, chargeback, lifecycle, and policy scope.
