# MyMagnet app patch: SQLite → Autonomous AI Database

`mymagnet-adb.patch` is a drafted change to
[rockkw/MyMagnet](https://github.com/rockkw/MyMagnet), made against commit
`e2641e0`. It hasn't been applied to the repo, and it hasn't been run against a
real database yet (the ADB isn't provisioned). It applies cleanly
(`git apply --check`) and every file compiles.

```bash
cd MyMagnet && git apply /path/to/mymagnet-adb.patch
```

## What changes

| File | Change |
|---|---|
| `magnet_db.py` (new) | python-oracledb **Thin mode** connection pool. Reads `MAGNET_DB_USER`, `MAGNET_DB_PASSWORD` and `MAGNET_DB_DSN`. A small wrapper keeps the `sqlite3` call shape (`conn.execute(sql, params)` with `?` placeholders, dict rows, `commit/close`), so call sites barely move. |
| `magnetlookup.py` | `open_db()` uses the pool. `INSERT OR IGNORE` / `ON CONFLICT` become `MERGE`; `lastrowid` becomes `RETURNING id INTO`; `MAX(a,b)` becomes `GREATEST`. New titles get `VECTOR_EMBEDDING(...)` on insert. A failed term now rolls back its partial writes. |
| `webserver.py` | `LIMIT` becomes `FETCH FIRST` / `OFFSET … FETCH NEXT`; `GROUP_CONCAT` + loose `GROUP BY` become a `LISTAGG(DISTINCT …)` scalar subquery; `LIKE` wraps both sides in `UPPER()` (SQLite's `LIKE` ignores case, Oracle's doesn't). Adds **`GET /api/similar?q=…&limit=…`** for vector similarity search. |
| `migrate_sqlite_to_adb.py` (new) | A one-time copy from a node's SQLite file (see below). |
| `requirements.txt`, `deploy/setup.sh` | Add `oracledb>=2.2` (2.2 is the first release with the VECTOR type). |
| `deploy/magnetlookup.env.example` | Add the `MAGNET_DB_*` variables. |

The JSON API keeps its shape. `torrents.size` is renamed to `torrent_size` in
the database because `SIZE` is an Oracle reserved word, and the queries alias it
back to `size`. The `--db PATH` flags are kept but now do nothing, so
`watch_terms.py` and the systemd units don't need to change.

The schema isn't created by the app any more. It lives in `../sql/03_schema.sql`.

## Rollout

1. Apply `lab-capstone-adb-stack`, then run `sql/01` to `sql/03` (see `../sql/README.md`).
2. On **each** instance, add these to `/etc/magnetlookup/env`:
   - `MAGNET_DB_DSN`: the `_tp` TLS connect string from `terraform output connection_profiles`. It must use port 1522, because that's the only port the NSG opens.
   - `MAGNET_DB_PASSWORD`: from Vault. The policy `mymagnet-adb-secret-read` lets the instance read it:
     ```bash
     oci secrets secret-bundle get --auth instance_principal \
       --secret-id <app_secret_id> \
       --query 'data."secret-bundle-content".content' --raw-output | base64 -d
     ```
     The instances don't have the OCI CLI installed. Install it into the venv with `pip install oci-cli`, or run this command from Cloud Shell and paste the result.
3. Apply the patch in `/opt/magnetlookup/app`, then run `pip install "oracledb>=2.2"` in the venv.
4. Migrate. The two instances have **different** SQLite files, so run on instance 1 first and then on instance 2 with `--merge`:
   ```bash
   set -a; . /etc/magnetlookup/env; set +a
   /opt/magnetlookup/venv/bin/python migrate_sqlite_to_adb.py /opt/magnetlookup/data/magnet_library.db            # instance 1
   /opt/magnetlookup/venv/bin/python migrate_sqlite_to_adb.py --merge /opt/magnetlookup/data/magnet_library.db    # instance 2
   ```
   The merge keeps the higher seed counts, the earliest first-seen time, the latest last-seen time, and the summed use counts. Searches from instance 2 get new ids.
5. Run `sql/04_embeddings_and_index.sql` to backfill embeddings and create the HNSW index.
6. Restart `magnetlookup-web`, and test with `curl 'http://localhost:8080/api/similar?q=ubuntu'`.

## Consequences for the rest of the stack

- **Run the scraper timer on one node only.** Both nodes now write to one
  database. If both run `magnetlookup.timer` with the same search terms, they
  scrape the same results twice, and two concurrent `MERGE`s on a brand-new
  `info_hash` can fail with ORA-00001 (the failed term is rolled back and
  logged). Disable the timer on instance 2 with
  `systemctl disable --now magnetlookup.timer`.
- **Sticky sessions aren't needed any more.** Both nodes see the same data, so
  the LB's `session_persistence_configuration` in `lab-mymagnet-stack` can be
  removed later. It's harmless to leave it.
- The SQLite files stay on disk as a fallback until the migration has been checked.

## Not verified (needs a live database)

- None of the SQL in the patch has been executed. It was checked against Oracle
  docs and by inspection only.
- Whether `FETCH APPROX FIRST ? ROWS ONLY` accepts a bind variable for the row count.
- Whether `ALTER TABLE … MODIFY id GENERATED BY DEFAULT ON NULL AS IDENTITY
  (START WITH LIMIT VALUE)` works as written on 26ai.
- Whether the `MERGE … VALUES (…, VECTOR_EMBEDDING(model USING s.title AS data))` form is
  accepted inside `MERGE`. The fallback is to insert NULL and let a periodic
  `sql/04` step 1 backfill it.
